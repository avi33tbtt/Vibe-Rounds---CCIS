## What this row is for

Let the person pick the `market/` folder on their device and show what is in it, or show why it was refused. Nothing is imported, selected or run yet. Later rows (3.8b to 3.8d) add the envelope, the selectors and the catalogue to the same page.

## Findings the build must handle

1. `loadMarket({ indexText, files })` is pure and all-or-nothing, and is the only gate. It takes the exact canonical text of `index.json` and a map from `artefacts/<id>/<version>.json` to exact text. Any extra stored file is refused (M-011). So the page must map the picked folder to that shape and must not guess.
2. `market/` also holds `.gitattributes` (`* -text`, so bytes are never rewritten). It is not an artefact. The mapping must skip it by exact name, and skip nothing else: any other unexpected file is passed on and refused by M-011, never hidden.
3. A folder pick gives paths like `market/artefacts/<id>/<version>.json` (the browser's relative path). The first segment is the folder name the person chose and is dropped. A pick whose top folder has no `index.json` is refused with M-001-shaped output, not a crash.
4. Reading is by `file.text()` on files the person chose. A byte-order mark or a changed line ending changes the checksum and `loadMarket` refuses with M-010. That is correct and stays: no normalising, no retry. The refusal view says "the bytes differ from the index", not "corrupt".
5. A refusal detail holds only ids, paths, versions and codes (never artefact values), so the refusal view may show it. Everything shown goes through `textContent` or `createElement`; no `innerHTML`, no inline handlers (CSP, D-063).
6. A market that loads is **not** a trusted market (CCIS-REQ-094, A-005): the checksum proves the same bytes, not who published them. The view says so in one line.

## Design (at most one row in `DECISIONS.md`)

- `ccis-app-market.js` (pure, no DOM, no clock): 
  - `marketInputFromFiles(items)` where `items` is `[{ path, text }]` with the folder-relative path: drops the top folder, skips only `.gitattributes`, finds `index.json`, returns `{ indexText, files }` or `{ ok: false, refusal }` (a fixed sentence, reusing M-001 wording; no new refusal ids).
  - `marketView(market)` returns rows `{ id, type, version, status, deprecated, checksumShort, warningCount, validationSummary }` in index order, plus counts by type. Never artefact bodies, never fixture values.
  - `refusalView(refusal)` returns `{ id, sentence, detail }` copied from `M_REFUSALS` text; unknown ids show the id and a fixed "unrecognised refusal" line.
- `ccis-app-market-view.js` (DOM, created through `document.createElement` and `textContent` only): a "Choose market folder" input (`webkitdirectory`), one `change` listener added with `addEventListener`, `file.text()` for each file, then render a table or the refusal. A "Clear" action empties the view and state. No storage of any kind, no network.
- `ccis-app.js` gains: `window.ccisApp.state()` reports `{ marketLoaded, entryCount, refused }` (counts and a boolean only). The stub's banners stay.
- The market view and refusal view are separate blocks in the template (one new `<section>`, no inline script or handler); the build and CSP hashes are regenerated by `node scripts/build-app.js`.

## Build

1. New: `ccis-app-market.js`, `ccis-app-market-view.js`. Edited: `ccis-app.js`, `ccis-app.template.html`, `ccis-app.css` (small), regenerated `index.html`.
2. New `test/ccis-app-market.test.js` (Node `--test`, jsdom for the view):
   - The committed `market/` folder, read by the test from disk, maps and loads; the view lists all six entries in index order with the same ids and versions as `index.json`.
   - `.gitattributes` is skipped; adding one other stray file gives M-011 in the refusal view; changing one byte of an artefact gives M-010 with that id and version; removing a file gives M-010; a folder without `index.json` is refused; an empty pick is refused. Nothing is partly loaded in any case.
   - A UTF-8 byte-order mark added to one artefact is refused (M-010), not stripped.
   - The refusal view and market view contain no artefact value: scan the rendered text for every string value of one artefact body and find none.
   - jsdom: the folder input change event renders the table through the bundle; Clear empties it and `state()` returns to zeros; no `innerHTML` assignment, no `fetch`, `XMLHttpRequest`, `localStorage`, `sessionStorage` or `indexedDB` reference in the two new modules.
   - `node scripts/build-app.js --check` still passes on the regenerated page; CSP hashes match; the 3.8 tests still pass.
